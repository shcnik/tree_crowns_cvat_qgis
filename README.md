# Разметка крон деревьев: GeoTIFF → DeepForest/SAM → CVAT → QGIS → датасет

Полуавтоматический конвейер **instance segmentation** деревьев на больших геопривязанных ортофотопланах с 6+ спектральными каналами. Рассчитан на разрешение 5–10 см/пиксель, но не привязан к нему. Не нуждается в CHM. Трёхканальный RGB используется **только для нейросети и CVAT**; итоговый экспорт берёт **все исходные каналы** непосредственно из GeoTIFF.

## Состав проекта

| Файл | Назначение |
|---|---|
| `00_inspect_raster.py` | CRS, разрешение, порядок и типы каналов TIFF |
| `01_detect_and_segment.py` | Детекция DeepForest + SAM ViT-B, полигональный GeoPackage, RGB stretch |
| `03_prepare_cvat.py` | RGB-тайлы для CVAT, начальные COCO-маски, манифест геопривязки и проверочная таблица |
| `04_collect_cvat.py` | COCO из CVAT → восстановление геопривязки и ID → GeoPackage + QA-отчёт |
| `02_export_dataset.py` | RGB/контур/маска и исходный многоканальный TIF, отдельные PNG по спектральным каналам |
| `crown_common.py` | Тайлинг, преобразования координат, COCO RLE (в том числе сжатый формат) |
| `tests/` | Офлайн-тест полного цикла на синтетическом 7-канальном GeoTIFF |

**Важное ограничение:** ML-инференс DeepForest/SAM зависит от весов, версии GPU-драйвера и фотографий леса. Его реальная точность на вашем ортофотоплане здесь **не проверялась**. Импорт/экспорт, геопривязка, ID и выходные изображения проверены на синтетических данных. COCO-пакет генерируется по спецификации CVAT; полноценная загрузка в работающий CVAT-инстанс также требует отдельной проверки.

## Исправление несовпадения устройств CPU/CUDA

В версии проекта с этой датой исправлена ошибка `Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor) should be the same`: DeepForest теперь настраивает Lightning Trainer (`model.create_trainer(accelerator='gpu' if device == 'cuda' else 'cpu', devices=1)`), а не перемещает вручную только `model.model` на GPU. Предсказания Lightning сами перемещают входной пакет и модель на выбранное устройство. SAM по-прежнему размещается отдельно через `sam.to(device)`.

Для проверки сначала запустите `--device cpu --max-tiles 1`, затем `--device cuda --max-tiles 1` на машине с CUDA. **Тест инференса на конкретной системе пользователя не выполнен**: потребуется локальная установка DeepForest, весов SAM и NVIDIA-среды.

## 1. Установка

Рекомендуется **Python 3.11**, Windows 11 + при наличии NVIDIA GPU. Чтобы избежать проблем с GDAL, удобна `micromamba`/`conda` для библиотек геоданных. Пример установки с использованием Python venv и pip:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-core.txt
```

Затем установите `torch`/`torchvision` с корректной сборкой CUDA (команда зависит от GPU и текущих сборок): https://pytorch.org/get-started/locally/ . После этого:

```powershell
python -m pip install -r requirements.txt
```

Для проверки без ML достаточно `python -m pip install -r requirements-test.txt` и `python -m pytest -q`.

Скачайте вес **SAM ViT-B** (`sam_vit_b_01ec64.pth`) по инструкции из https://github.com/facebookresearch/segment-anything#model-checkpoints . Вес **DeepForest** загрузится через модель `weecology/deepforest-tree` при первом запуске. Для первого получения весов нужен интернет. CVAT устанавливается/используется отдельно: https://docs.cvat.ai/ . **Не помещайте веса SAM и свои большие GeoTIFF внутрь архива проекта.**

## 2. Выяснить порядок каналов

```powershell
python 00_inspect_raster.py forest.tif
```

По метаданным сенсора определите **номера R/G/B**. Они отсчитываются с **1**. В примерах используются `3 2 1`, но это лишь пример. Если для точного определения Red/Green/Blue не хватает названий каналов, смотрите паспорт сенсора. Предобученный DeepForest работает по RGB-представлению, а не непосредственно по 6+ каналам.

## 3. Получить первоначальную разметку

```powershell
python 01_detect_and_segment.py <путь к файлу с планом> crowns_auto.gpkg --rgb 3 2 1 --sam-checkpoint sam_vit_b_01ec64.pth --core 512 --margin 192
```

Результат: `crowns_auto.gpkg` (слой `crowns`, поле `tree_id`) и `crowns_auto_stretch.json` (общие пределы RGB-растяжения). Детектор назначает дерево тайлу по центру bounding box; зоны перекрытия тайлов уменьшают, но не исключают пограничные ошибки. При использовании строго одинаковых настроек `--core` и `--margin` на следующих шагах обычно проще разбираться со швами.

При отсутствии весов/ресурсов можно пропустить модель: создать `crowns_auto.gpkg` с геопривязанными полигонами, уникальным текстовым `tree_id` и слоем `crowns` в QGIS. Для `03_prepare_cvat.py` также нужен stretch JSON (пример: `{"rgb_bands_1_based":[3,2,1],"limits_2_98":[[0,65535],[0,65535],[0,65535]]}` для корректных диапазонов конкретного снимка).

## 4. Подготовить изображения и аннотации CVAT

```powershell
python 03_prepare_cvat.py <путь к файлу с планом> crowns_auto.gpkg crowns_auto_stretch.json cvat_input --core 512 --margin 192
```

Создаются:

```text
cvat_input/
  cvat_images.zip           # ВСЕ тайлы для загрузки как изображения задачи
  cvat_annotations.zip      # начальные COCO 1.0 маски, отдельно от изображений
  instances_default.json    # те же аннотации без ZIP
  tile_manifest.json        # САМОЕ ВАЖНОЕ: сохранять до завершения проекта
  tiles_for_review.csv      # список тайлов, число предварительно обнаруженных крон
  images/                   # PNG, которые можно использовать вместо ZIP
  core_guides/              # PNG с РОЗОВОЙ рамкой центральной рабочей зоны
```

**Не загружайте `core_guides/` вместо `images/`**: направляющая рамка есть только на справочных картинках. Истинная рабочая зона каждого тайла записана также в `tiles_for_review.csv` как координаты `[core_local_x0, core_local_y0, core_local_x1, core_local_y1)`.

Если нужно проверить первые 4 тайла: `--max-tiles 4` (при полном прогоне убрать). По умолчанию выгружаются и **пустые тайлы** — это важно для поиска деревьев, пропущенных автоматическим детектором. Флаг `--only-with-annotations` отключает это поведение и **не подходит для окончательной разметки**.

Упаковка изображений может занимать много места: `--no-images-zip` оставляет только PNG в папке `images/`.

## 5. Работа в CVAT

1. Откройте **CVAT**: отдельный сервер/локальный Docker или CVAT Online. Если загружать тайлы в облачный сервис нельзя по условиям лицензии/конфиденциальности, используйте локальный CVAT.
2. Создайте **Task** с типом изображений и единственной меткой **`tree`**. Добавьте изображения из `cvat_images.zip` (или `images/`). Убедитесь, что сохранились исходные имена и размеры PNG.
3. В меню **Actions → Upload annotations** выберите **COCO 1.0** и импортируйте `cvat_annotations.zip` или `instances_default.json`.
4. Исправляйте **маски/полигоны отдельных деревьев**: разделяйте слившиеся, добавляйте пропущенные, удаляйте ложные. При наличии SAM Interactor можно использовать его внутри CVAT; этот плагин не обязателен для обмена данными.
5. **Правило владения:** размечайте каждое дерево **только в том тайле, в центральную зону которого попадает центр его ограничивающего прямоугольника**. Контекст вокруг центра виден, но не является второй областью для создания дубликатов. Локальные границы центра указаны в CSV и на справочном PNG из `core_guides/`.
6. Важно проверить также тайлы с `initial_tree_count=0`. CVAT не может автоматически показать полностью пропущенное деревo как ошибку существующей маски.
7. После проверки всей задачи экспортируйте **Dataset → COCO 1.0** (или *Export annotations*, если предлагается COCO 1.0) как ZIP/JSON. **Не путать с первоначальным `cvat_annotations.zip`**; сохраните исправленный файл отдельно, например `cvat_reviewed.zip`.

Ссылки на спецификацию и шаги: https://docs.cvat.ai/docs/manual/advanced/formats/format-coco/ и https://docs.cvat.ai/docs/manual/advanced/import-datasets/ . COCO может содержать полигоны или сжатые/несжатые RLE маски. Начальная разметка экспортируется в RLE; для технической совместимости начальный флаг `iscrowd=1` используется как требование масочного представления, а **не как указание на группу деревьев**. Для обучения на COCO поле `iscrowd` нужно нормализовать до целевой семантики.

## 6. Забрать исправленную разметку из CVAT

```powershell
python 04_collect_cvat.py cvat_reviewed.zip cvat_input/tile_manifest.json crowns_auto.gpkg crowns_reviewed.gpkg --match-iou 0.30
```

Принимает COCO 1.0 ZIP либо JSON. Вытаскивает RLE/полигон, применяет сдвиг тайла и CRS-геотрансформацию из манифеста. Затем пытается сопоставить исправленный объект с исходным по IoU ≥ 0.30 и сохранить исходный `tree_id`. Если уверенно сопоставить не удалось, создаёт новый ID (например, `T000278`). Это **геометрическое эвристическое сопоставление**, при больших смещениях/слияниях ID придётся проверить вручную.

Итоги:

- `crowns_reviewed.gpkg` — полигоны в исходной CRS, `tree_id`, `status`, `review_needed`, `flags`, поля качества.
- `crowns_reviewed_qa.json` — `matched`, `new_ids`, `unmatched_seed_ids`, `ignored_outside_core`, `duplicate_mask_warnings` и другие события.

Удалённая во время проверки крона **не включается** в новый GPKG. Объекты, принадлежащие вообще не входившим в CVAT-задачу тайлам (например, при тестовом `--max-tiles 4`), **сохраняются, но помечаются `not_reviewed`**.

По умолчанию скрипт **останавливается**, если CVAT-экспорт не содержит какой-либо тайл из `tile_manifest.json`: это защита от незаметного удаления деревьев. Для заведомо неполного экспорта можно добавить `--allow-missing-images`; такие тайлы останутся непроверенными.

Если аннотатор создал объект вне центральной рабочей области своего тайла, он **не попадёт в итоговую разметку**: подробности в `ignored_outside_core`. Проверять этот список обязательно. Объекты только с `bbox` (без маски/полигона) **не экспортируются как кроны**, их номера попадают в `ignored_no_segmentation`.

## 7. Проверить результат в QGIS

Откройте `forest.tif` и `crowns_reviewed.gpkg`, слой `crowns`. Проверьте все записи в `crowns_reviewed_qa.json`, в особенности `new_ids`, `unmatched_seed_ids`, `duplicate_mask_warnings`, `ignored_outside_core`. Просмотрите границы тайлов и несколько участков с плотной кроной. QGIS можно использовать для последних правок. При сохранении GeoPackage оставьте слой с именем **`crowns`** и уникальные `tree_id`.

**Осторожно:** для последующих повторных импортов в CVAT используйте исходный `crowns_auto.gpkg` как *seed*, а не уже исправленный файл. Не импортируйте в CVAT другой порядок/размер тайлов без пересоздания манифеста.

## 8. Финальный экспорт 6+ спектральных каналов и масок

```powershell
python 02_export_dataset.py <путь к файлу с планом> crowns_reviewed.gpkg dataset --stretch crowns_auto_stretch.json --manifest cvat_input/tile_manifest.json --pad 16
```

Для каждого дерева создаётся:

```text
dataset/
  index.csv
  T000001/
    rgb.png               # визуальный RGB-кроп
    contour.png           # RGB-кроп с линией контура
    mask.png              # 255 = крона, 0 = фон
    masked_rgb.png        # RGB с чёрным фоном вне маски
    multispectral.tif     # ВСЕ исходные каналы + CRS + исходные значения
    metadata.json         # координаты, окно, спектральные каналы, геометрия
    bands/
      band_01.png         # исходные uint8/uint16 значения в отдельном PNG
      band_02.png
      ...
```

Для данных типа `float32`, `int16`, `uint32` отдельные файлы в `bands/` будут называться `band_XX_preview.png` и являются только визуальными нормированными представлениями. Никаких исходных спектральных значений не теряет **только** `multispectral.tif`; многоканальный PNG для всех 6+ исходных каналов как единый стандартный PNG не создаётся. Кропы имеют разный размер, соответствующий кроне и `--pad`. Для обучения с одинаковым размером потребуется последующее padding/resizing, причём *интерполяция масок только nearest-neighbor*.

## 9. Проверка офлайн без нейросетей

```powershell
python -m pip install -r requirements-test.txt
python -m pytest -q
```

Тест создаёт искусственный 7-канальный GeoTIFF с **повёрнутым аффинным преобразованием**, исходные полигоны, заполняет тайлы с перекрытием, моделирует удаление/добавление крон в COCO, восстанавливает GPKG и запускает финальный экспорт PNG/TIF. Настоящие модели и CVAT-сервер в тесте не запускаются.

## Важные ограничения и методика качества

- **Нельзя оценивать качество только по исправленным детекциям**: смотрите на тайлы без детекций и независимые площадки. Отмечайте пропущенные кроны, Precision/Recall и Mask IoU.
- Кроны, расположенные под верхним пологом, нельзя достоверно извлечь по одному ортофотоплану без дополнительных данных.
- Разделяйте тренировочную/валидационную/тестовую выборки по географическим участкам, а не случайно по соседним деревьям.
- При малом перекрытии тайлов большая крона может быть усечена; отражается в QA-поле `touches_image_edge`. Если это частая ошибка, увеличивайте `--margin` при подготовке CVAT и при модельном инференсе.
- `review_needed` — только подсказка; `status='edited'` означает прохождение через CVAT, но **не гарантирует**, что человек действительно просмотрел объект. При командной разметке подтверждайте это в самом CVAT.
- На диске понадобятся временные RGB-тайлы и ZIP, их размер может быть значителен. Не загружайте весь GeoTIFF в память.
- Из-за использования `iscrowd=1` для предварительных RLE в COCO не используйте этот COCO как финальную обучающую разметку без проверки/нормализации соответствующего флага. Первичный обучающий датасет рекомендуется строить из итоговых `mask.png` + `multispectral.tif`.


## Диагностика: No crowns were detected

`--max-tiles 4` без дополнительных аргументов означает первые четыре тайла
верхней строки изображения. Они могут не содержать леса. Для выбора
определённого тайла используйте 0-based координаты строки/столбца:

```powershell
python 01_detect_and_segment.py forest.tif crowns_test.gpkg `
  --rgb 3 2 1 --sam-checkpoint sam_vit_b_01ec64.pth `
  --tile-row 5 --tile-col 8 --debug-dir diagnostics
```

`--tile-row` и `--tile-col` без `--max-tiles` обрабатывают ровно один тайл.
Для обработки нескольких последовательных тайлов добавьте `--max-tiles 4`.
Другой вариант — `--start-tile 100 --max-tiles 4` (порядок строка за строкой).

В `diagnostics/` сохраняются RGB-изображения, картинки с рамками детекций
и `diagnostics.csv`, где видно, сколько рамок нашёл DeepForest и сколько
отброшено фильтрами.

Если RGB действительно содержит кроны, но модель не видит рамки, можно
**диагностически**, не для окончательной разметки, снизить внутренний порог:

```powershell
python 01_detect_and_segment.py forest.tif crowns_test.gpkg `
  --rgb 3 2 1 --sam-checkpoint sam_vit_b_01ec64.pth `
  --tile-row 5 --tile-col 8 --df-score-thresh 0.05 `
  --min-confidence 0.05 --debug-dir diagnostics
```

Важно: понижение только `--min-confidence` не понизит собственный
внутренний порог предсказаний DeepForest.
Проверьте реальные номера каналов Red, Green и Blue.
Если детектор не распознаёт кроны и на правильном RGB,
потребуется дообучение либо смена детектора.
